# BUILD VIDEO PROMPT — Paste into Claude Code or Codex

Render the storyboard at:

`stories/{{STORY_SLUG}}.json`

Follow `CLAUDE.md` if running Claude Code, or `AGENTS.md` if running Codex. These standing instructions are binding. The goal is a **cinematic, finished 45–90-second (storyboard-selected), vertical 1080×1920 30fps MP4** produced from real animated Three.js scenes, with peaceful adult male voice, accurate burnt-in subtitles and restrained soundtrack. No slideshow/stock footage substitute and no paid APIs.

## Mandatory run sequence
1. Validate storyboard and timeline, verify the science/visual rules and intended duration. Open `assets/registry.json`, reuse matching assets from earlier videos before writing new geometry/shaders/textures/models. Treat storyboard candidate assets as requests, not already-built source code.
2. Build **all** shots, camera movements, effects, world environments and human/ecological impacts. Extract truly reusable new work into `src/library/` or `assets/library/`; register the real files in `assets/registry.json` with stable IDs, public config inputs, reuse tags, source paths, license and `created_for`. Preserve prior-video compatibility. Do not register phantom assets.
3. Generate local licensed calm male narration; synchronize styled caption burn-in to the actual audio; mix subtle legal/original sound design. Frame-render deterministically and encode `output/{{STORY_SLUG}}.mp4` using H.264/yuv420p, AAC 48kHz stereo and `+faststart`. The same final render writes the thumbnail `output/{{STORY_SLUG}}.jpg`: a 1080×1920 JPG ≤ 2 MB bold cover from the clean still at `thumbnail.time_s`: punch-in on the subject, huge outlined `thumbnail.headline`, red `badge` sticker and an arrow to the subject, true to the film, styled (font, colours, grade) for the video's niche and subject (`node tools/render.mjs {{STORY_SLUG}} --thumbnail` regenerates only it).
4. Run minimal critical QA: storyboard validity, three visual smoke frames, the thumbnail (subject readable, headline clear of it), actual `ffprobe` format/audio/duration verification and MP4 exists. Skip unrelated unit tests, huge E2E suites, broad lint/refactoring or test reports.
5. **After successful MP4 creation**, compose `metadata/{{STORY_SLUG}}.json` based on `examples/moon-half-distance.metadata.example.json`. Produce *different* accurately searchable upload metadata for YouTube Shorts, Instagram Reels, Facebook Reels, TikTok and X: platform-ready titles/descriptions/captions/posts, hashtags, topic search keywords, and YouTube tags. Copy rules (the finalizer enforces them): every platform carries **5–15 relevant hashtags** (no generic spam), and every platform's title starts with **"What if"**: the YouTube Shorts and Facebook Reels titles, and the opening line of the Instagram and TikTok captions and the X post, which have no title field. The X post plus its hashtags stays within 280 characters. Use only claims and events present in the finished film. Include exact new/reused asset IDs; do not invent publication URLs.
6. **Run `python scripts/finalize_video.py {{STORY_SLUG}}`**, which verifies media/metadata and the copy rules and generates the publishing copy `output/{{STORY_SLUG}}.md` (ready-to-paste text for all five platforms), `metadata/{{STORY_SLUG}}.md` and cumulative `VIDEO_CATALOG.md` containing each video's copy-paste metadata; also updates the reuse registry and `ASSET_LIBRARY.md`. Must succeed before declaring completion.
7. **Upload to Hugging Face (required for every video).** After finalizing, upload `output/{{STORY_SLUG}}.mp4`, its thumbnail `output/{{STORY_SLUG}}.jpg` and its publishing copy `output/{{STORY_SLUG}}.md` to the creator's private Hugging Face dataset repo set in `huggingface.json` (`Whatif2203/whatif`), into the one shared `videos/` folder as `<NNN>-{{STORY_SLUG}}.mp4`, `<NNN>-{{STORY_SLUG}}.jpg` and `<NNN>-{{STORY_SLUG}}.md`, all three under the same number in one commit. NNN is the next zero-padded number after the highest already in that folder, read from the Hub at upload time so other developers' uploads count; a film that already has a number keeps it and its files are replaced. `node tools/finalize.mjs {{STORY_SLUG}}` does it automatically: finalize → `python scripts/upload_to_hf.py {{STORY_SLUG}}` → finalize again so the links appear in `metadata/{{STORY_SLUG}}.md` and `VIDEO_CATALOG.md`. Unchanged files are skipped, simultaneous uploads are retried safely, and `python scripts/upload_to_hf.py --all` uploads every finished video in `output/`. Never read, print or commit the Hugging Face token.
